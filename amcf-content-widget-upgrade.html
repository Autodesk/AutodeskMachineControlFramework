Content Widget Upgrade

Evolving the content module from a plain div wrapper into a configurable card widget — with card style variants, professional headers, vertical-stack spacing, and full-height layout.

Overview

The Content module is the primary layout container for child sub-modules (forms, lists, charts, layer views, …). Today it renders as plain, unstyled divs with a raw title string — no visual grouping, no configurable spacing, and no consistent height behaviour.

This upgrade adds four configurable card styles, a vertical gap control between stacked children, and ensures the widget always fills 100 % of its allocated height in Grid cells and standalone page columns.

All new attributes have safe defaults, so existing XML configurations require no changes.

What stays the same

  • headline, title, subtitle, caption attributes
  • visible dynamic expression support
  • Child sub-module rendering via Module_Factory
  • Legacy JSON serialisation path
  • All existing XML configurations work without modification

What is added

  • cardstyle — one of none / elevated / outlined / tinted
  • spacing — px gap between vertically stacked children
  • elevation — shadow depth for the elevated style
  • cardcolor — background colour override for tinted style
  • Full-height behaviour (height: 100% through the component tree)

New XML Attributes

All attributes are optional. Defaults reproduce the pre-upgrade appearance.

Attribute Type Default Description
cardstyle string enum none Visual card treatment. One of none, elevated, outlined, tinted.
spacing integer (px) 0 Gap in pixels between vertically stacked child sub-modules.
elevation integer 0–24 2 Vuetify shadow elevation for the elevated card style.
cardcolor CSS color string empty Background colour override, primarily used with tinted. Accepts hex, rgb(), or named colours.

Example XML

<content name="buildstatus"
         title="Build Status"
         subtitle="Live process information"
         cardstyle="elevated"
         spacing="12"
         elevation="3">

  <form name="status" />
  <layerview name="viewer" />

</content>

<!-- Tinted, custom colour -->
<content name="warnings"
         title="System Alerts"
         cardstyle="tinted"
         cardcolor="#fff8e8"
         spacing="8">
  <alertlist name="alerts" />
</content>

Vertical Spacing Control

How it works

The children wrapper uses display: flex; flex-direction: column. The spacing attribute maps directly to CSS gap:

gap: 12px;   /* spacing="12" */
flex: 1 1 0;
min-height: 0;  /* allows shrink */

This is the same philosophy used by the Grid module's column/row gap. The children do not need to know about spacing — it is managed entirely by the parent container.

Key Snippets

C++ — constructor (content.cpp)

// parse new attributes
auto cardStyleAttrib = xmlNode.attribute("cardstyle");
m_sCardStyle = cardStyleAttrib.empty() ? "none" : cardStyleAttrib.as_string();

m_nSpacing   = (uint32_t) xmlNode.attribute("spacing").as_int(0);
m_nElevation = (uint32_t) xmlNode.attribute("elevation").as_int(2);
m_sCardColor = xmlNode.attribute("cardcolor").as_string();

// register as v2 attributes
CUIExpression cardStyleExpr; cardStyleExpr.setFixedValue(m_sCardStyle);
CUIExpression cardColorExpr; cardColorExpr.setFixedValue(m_sCardColor);
registerStringAttribute("cardstyle", cardStyleExpr);
registerStringAttribute("cardcolor", cardColorExpr);
registerIntegerAttribute("spacing",   CUIExpression::fromInteger(m_nSpacing));
registerIntegerAttribute("elevation",  CUIExpression::fromInteger(m_nElevation));

JavaScript — AMCModule_Content.js

// constructor
this.cardstyle  = moduleJSON.cardstyle  || "none";
this.spacing    = moduleJSON.spacing    || 0;
this.elevation  = moduleJSON.elevation  || 2;
this.cardcolor  = moduleJSON.cardcolor  || "";

// updateFromV2Attributes
if (attrs.cardstyle  !== undefined) this.cardstyle  = attrs.cardstyle;
if (attrs.spacing    !== undefined) this.spacing    = parseInt(attrs.spacing)  || 0;
if (attrs.elevation  !== undefined) this.elevation  = parseInt(attrs.elevation) || 2;
if (attrs.cardcolor  !== undefined) this.cardcolor  = attrs.cardcolor;

Vue template — AMCModule_Content.vue (structure)

<template>
  <div class="content-root">

    <!-- Card styles: elevated / outlined / tinted -->
    <v-card v-if="module.cardstyle !== 'none'"
            :outlined="module.cardstyle === 'outlined'"
            :elevation="module.cardstyle === 'elevated' ? module.elevation : 0"
            :color="cardBackground"
            class="content-card">
      <v-card-title    v-if="module.title">{{ module.title }}</v-card-title>
      <v-card-subtitle v-if="module.subtitle">{{ module.subtitle }}</v-card-subtitle>
      <v-card-text class="content-children" :style="childStyle">
        <Module_Factory v-for="m in module.modules" :key="m.uuid" … />
      </v-card-text>
    </v-card>

    <!-- style="none" — plain divs, unchanged appearance -->
    <template v-else>
      <div v-if="module.title"    class="content-title">…</div>
      <div v-if="module.subtitle" class="content-subtitle">…</div>
      <div class="content-children" :style="childStyle">
        <Module_Factory … />
      </div>
    </template>

  </div>
</template>

// computed
childStyle () {
  return { gap: this.module.spacing + 'px' };
}
cardBackground () {
  if (this.module.cardstyle === 'tinted')
    return this.module.cardcolor || '#eaf1fb';
  return '';
}

Backward Compatibility

Safe defaults

  • cardstyle defaults to "none" → existing plain-div rendering unchanged
  • spacing defaults to 0 → no gap added
  • elevation defaults to 2 → only visible when style is elevated
  • cardcolor defaults to "" → falls back to primary theme tint

No API constant changes

The four new attribute names (cardstyle, spacing, elevation, cardcolor) are short, unambiguous string literals used directly — no new #define entries in amc_api_constants.hpp are required.

Legacy JSON path

The new attributes are written to writeLegacyDefinitionToJSON so that any legacy polling path receives them too, preventing blank-screen regressions on older frontend builds.
